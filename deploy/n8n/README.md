# n8n 자동 트리거 (확장 4)

사람이 시작하지 않아도 월요일 아침에 제작이 시작되도록 하는 워크플로다.

```
월요일 06:00  →  POST /runs  →  에이전트가 조사까지 하고 waiting_for_user 로 멈춤
담당자 출근    →  화면에 뜬 질문에 답만 하면 이어짐
```

**n8n 은 트리거만 담당한다.** 무엇을 조사하고 어떤 카드를 만들지는 앱의 에이전트가 정한다.
판단을 n8n 노드로 옮기면 그건 자동화이지 에이전트가 아니다 (`DECISIONS.md` D-006).

## 왜 앱을 수정하지 않았나

`POST /runs` 가 이미 폼 데이터(`topic`, `region`)를 받는다. 화면에서 사람이 누르는 것과
n8n 이 부르는 것이 **같은 입구**다. 트리거를 붙이려고 별도 API 를 만들면
사람 경로와 자동 경로가 갈라져 둘 중 하나는 시험되지 않은 채 남는다.

## 임포트 절차

1. n8n 좌상단 **⋯ → Import from File** → `mq4-cardnews-schedule.json` 선택
2. **Save** (아직 Active 로 켜지 말 것)
3. `제작 시작 (POST /runs)` 노드에서 `topic` · `region` 을 원하는 값으로 바꾼다
4. **Execute Workflow** 로 1회 수동 실행 → 마지막 노드에 `run_url` 이 나오면 성공
5. 그 주소를 열어 실행이 실제로 진행 중인지 확인
6. 확인됐으면 **Active** 로 켠다

### 켜기 전에 확인할 것

앱과 터널이 살아 있어야 한다. 죽어 있으면 마지막 노드가 오류를 던진다 (조용히 넘어가지 않는다).

```bash
curl -s https://cardnews.dodami-ai.com/healthz
```

## 🔴 실서비스와 섞지 않기

이 n8n 인스턴스에는 **온담이·이음이가 함께 있다.** 같은 인스턴스를 쓰기로 했으므로
(D-021) 분리 장치를 지킨다.

- 워크플로 이름의 접두어 **`mq4-`** 를 바꾸지 않는다
- **자격증명을 새로 만들고** 기존 것을 재사용하지 않는다
- 실서비스 워크플로는 **열지 않는다**
- 이 JSON 을 저장소에 커밋해두므로, 계정 상태와 무관하게 구현 증거가 남는다

## 설계 메모 — 리다이렉트를 따라가지 않는 이유

`POST /runs` 는 `303` 으로 `/runs/<run_id>` 를 돌려준다.
n8n 이 리다이렉트를 따라가면 HTML 페이지만 받아서 **어느 실행이 시작됐는지 알 수 없다.**
그래서 `followRedirects: false` + `fullResponse: true` 로 두고
**Location 헤더에서 `run_id` 를 꺼낸다.**

`neverError: true` 는 HTTP 노드가 상태 코드로 실패를 던지지 않게 한 것이고,
대신 다음 노드에서 `303` 인지 직접 확인한다.
**"응답이 왔다" 와 "제작이 시작됐다" 는 다르다** — 이 프로젝트가 반복해서 지킨 원칙이다.
